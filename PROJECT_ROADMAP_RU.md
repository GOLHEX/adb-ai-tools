# Roadmap проекта

## Цель продукта

Создать локальное приложение для аудита профиля Adobe Stock Contributor, подготовки и проверки улучшений метаданных, безопасного применения подтверждённых изменений и, позднее, подготовки новых загрузок. Каждая операция должна быть наблюдаемой, обратимой и защищённой от несоответствия ассета.

## Фаза 0: Стабилизация восстановленного прототипа

**Результат:** текущий workflow воспроизводится на чистой машине.

- Оставить одну каноническую копию `adobe_edit.js` и устранить расхождения между дубликатами.
- Исправить или удалить batch-файлы, которые ссылаются на отсутствующий `adobe_agent.js`.
- Вынести настройки в переменные окружения или локальный конфигурационный файл.
- Добавить явные ненулевые коды завершения при ошибках.
- Добавить проверку схемы CSV и понятные сообщения об ошибках.
- Добавить smoke-тесты для harvest, dry-run, защиты проданных и уже изменённых работ.
- Описать требования к живой Adobe-сессии.

**Готово, когда:** на чистой машине документированный workflow запускает harvest, dry-run и mock apply.

## Фаза 1: Безопасная доменная модель и хранение

**Результат:** файловое состояние становится запросным и аудируемым.

- Создать TypeScript-проект и сохранить рабочую Adobe-интеграцию за интерфейсом адаптера.
- Добавить SQLite и миграции Drizzle.
- Реализовать таблицы `Asset`, `MetadataRevision`, `Review`, `Run`, `Sale`, `Rejection` и `Theme`.
- Импортировать portfolio CSV, данные продаж, отклонённые работы и theme registry.
- Обеспечить уникальность `media_id` и проверку актуального `contentUuid`.
- Сохранять хеш входного файла, время, источник, версию правил и ID запуска.
- Сделать применённые ревизии неизменяемыми и хранить старые значения.

**Готово, когда:** повторный импорт одного источника идемпотентен, а каждое изменение метаданных связано с запуском и подтверждением.

## Фаза 2: Валидатор и workflow подтверждения

**Результат:** небезопасная партия не может попасть в Adobe.

- Проверять title, keywords, category, дубликаты, порядок keywords и лимиты полей.
- Выявлять дубликаты и подозрительно похожие ассеты, когда доступны данные.
- Сравнивать предлагаемые метаданные с последним harvest.
- Требовать актуальные данные защиты проданных работ.
- Формировать dry-run diff с точными телами запросов без секретов.
- Добавить состояния approve, reject, cancel и retry.
- Требовать успешный preflight перед live apply.
- Создавать backup/export перед массовым применением.

**Готово, когда:** live apply невозможен без актуальных данных, валидных метаданных, подтверждения и успешного dry-run.

## Фаза 3: Интерфейс оператора

**Результат:** workflow работает без ручного редактирования CSV.

- Добавить Fastify API для ассетов, ревизий, запусков, импортов и подтверждений.
- Добавить React/Vite-экраны списка ассетов, фильтров, preview, сравнения метаданных и batch review.
- Явно показывать состояния sold, edited, unreviewed, failed и approved.
- Добавить повторный запуск неудачных операций без повторения успешных.
- Показывать прогресс и журнал операций без секретов.
- Оставить UI и API локальными по умолчанию.

**Готово, когда:** оператор может импортировать harvest, проверить партию, подтвердить её, выполнить dry-run и apply из UI.

## Фаза 4: Аналитика портфеля

**Результат:** рекомендации основаны на данных, а не на интуиции.

- Создать контролируемую и версионируемую таксономию тем.
- Считать доход на работу и показывать размер выборки.
- Добавить cohort analysis по дате загрузки, задержке первой продажи, сезонности и причинам отклонений.
- Измерять similarity, пересечения keywords и повторяемость контента.
- Разделять влияние контента и влияние метаданных.
- Формировать рекомендации с абсолютными объёмами, периодом и оговорками о неопределённости.
- Экспортировать воспроизводимые отчёты.

**Готово, когда:** каждая рекомендация связана с исходными данными, фильтрами и воспроизводимым запросом.

## Фаза 5: AI-assisted подготовка метаданных

**Результат:** AI ускоряет черновую работу, но не получает неконтролируемый доступ к записи.

- Подключить провайдера анализа изображения через интерфейс.
- Генерировать draft title, keywords, category, confidence и rationale.
- Проверять утверждения по видимому preview и правилам метаданных.
- Поддержать ручное редактирование и историю подтверждений.
- Измерять долю принятых предложений, исправлений и отклонённых рекомендаций.
- Разделить generation, approval, dry-run и apply на отдельные состояния.

**Готово, когда:** AI создаёт полезные черновики для очереди review, но не может применить их без явного подтверждения.

## Фаза 6: Подготовка новых загрузок

**Результат:** новый контент подготавливается безопасно.

- Добавить validator имён и генерацию upload manifest.
- Добавить квоты theme/subtheme и проверки дубликатов.
- Добавить similarity preflight относительно локального портфеля.
- Отслеживать состояния candidate, prepared, uploaded, submitted, accepted и rejected.
- Подключать upload workflow Adobe только после стабилизации работы с опубликованными ассетами.

**Готово, когда:** система создаёт проверяемую upload-партию и корректно восстанавливается после частичного сбоя.

## Решение по стеку

Начать с TypeScript и Node.js 22, Playwright/CDP, Fastify, React/Vite, SQLite/Drizzle, Zod, Pino, Sharp, CSV parser и Vitest. Использовать modular monolith. Переходить на PostgreSQL, фоновые workers или hosted deployment только при появлении нескольких операторов или нагрузки, оправдывающей усложнение.

## Первый срез реализации

Первый coding slice должен включать Фазу 0 и минимум Фазы 1:

1. Создать TypeScript-проект и тестовую инфраструктуру.
2. Обернуть текущий Adobe script интерфейсом адаптера.
3. Добавить строгие схемы для harvested assets и apply CSV.
4. Добавить SQLite с сущностями `Asset`, `Run` и `MetadataRevision`.
5. Реализовать команды import и dry-run.
6. Добавить тесты защиты sold assets, проверки UUID и redaction секретов.

Этот срез создаёт надёжный фундамент до UI и AI.
